Formulario de ABM

1) Que se practica aca

ABM significa Alta, Baja y Modificacion: las tres operaciones basicas sobre un registro. El formulario del medio es un div con position: fixed, anclado al viewport y mostrado como una ventana modal: aunque se escrolee este texto, el formulario no se mueve.

Los botones arrancan deshabilitados. En cada keyup y en cada focus de los inputs se llama a la funcion todoListo(), que valida el formulario completo con checkValidity() y habilita o deshabilita los botones con la propiedad disabled (pag. 13, 14 y 15 del apunte).

El boton Blanquear se habilita apenas hay algun dato cargado. Alta, Modi y Baja se habilitan solo si el formulario valida: apellido y nombres completos y el saldo entre 100 y 1000. Si se deja de cumplir alguna condicion, vuelven a deshabilitarse.

Cada operacion pide confirmacion con confirm(), asigna el action que corresponde (alta.html, modi.html o baja.html), el method get, y envia el formulario con submit() en una pestana nueva (pag. 12).

2) Las instrucciones que hacen el trabajo

  • window.addEventListener("load", function() { cargaInicial(); }); → evento de carga inicial del documento.
  • objApellido.addEventListener("keyup", function() { todoListo(); }); → se ejecuta cada vez que se introduce un caracter.
  • objApellido.addEventListener("focus", function() { todoListo(); }); → se ejecuta al enfocar el input.
  • objBtAlta.disabled = true; → true deshabilita y false habilita el boton.
  • objApellido.select(); → pone el foco en el input para escribir.
  • var confirma = confirm("Esta seguro de enviar"); → devuelve true si se acepta y false si se cancela.
  • objFormulario.reset(); y objFormulario.submit(); → reset y envio desde JavaScript.

3) Texto de relleno para escrolear

Programación en Ambiente de Redes estudia como se construyen aplicaciones que viven repartidas entre un cliente y un servidor. Del lado del cliente, el navegador recibe documentos HTML, les aplica estilos CSS y ejecuta codigo JavaScript que le da comportamiento a cada elemento. Del lado del servidor, un programa recibe los requerimientos, consulta una base de datos y devuelve respuestas.

Un formulario de ABM es la pieza tipica de esas aplicaciones: permite dar de alta un registro nuevo, modificar uno existente o darlo de baja. Antes de mandar nada al servidor conviene validar los datos en el cliente, para no generar requerimientos inutiles y para darle al usuario una respuesta inmediata cuando se equivoca.

La validacion HTML5 se declara con atributos como required, min, max, pattern o type. El navegador la ejecuta sola al enviar un formulario con un boton submit, pero desde JavaScript podemos consultarla en cualquier momento con el metodo checkValidity(), aplicado a un input o al formulario completo.

Los eventos del teclado son una buena oportunidad para hacerlo: keydown ocurre al bajar la tecla, keypress mientras se pulsa y keyup cuando se suelta. En keyup el valor del input ya incluye el caracter recien escrito, por eso es el evento que usamos para validar.

Cuando el formulario se envia con method get, las variables viajan en la URI del requerimiento, despues del signo de pregunta. Con method post viajarian en el body y la barra de direcciones se veria limpia. En las proximas unidades las paginas alta, modi y baja van a ser programas del servidor que reciban esas variables y operen sobre una tabla de la base de datos.

Mas adelante tambien vamos a ver que los datos no siempre viajan en un formulario: JavaScript puede enviar y recibir objetos de datos convertidos a texto JSON sin recargar la pagina, y con la creacion dinamica de objetos del DOM armar tablas completas a partir de lo que devuelve el servidor.

Mientras tanto, lo importante de este ejercicio es separar las responsabilidades: el HTML declara que datos se piden y que reglas deben cumplir, el CSS decide como se ve la ventana modal, y JavaScript decide cuando se habilita cada operacion y hacia donde se envia el formulario.
